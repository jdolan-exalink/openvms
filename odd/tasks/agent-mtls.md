# Agent mTLS for the gRPC control channel

## Objective

Give every edge agent a unique, revocable X.509 identity issued by an internal CA, and require that identity on a dedicated agent gRPC listener, so the API knows which server and tenant each heartbeat comes from.

## Problem

`NodeServer.Heartbeat` (`internal/control/node.go`) accepts any `node_id` without authentication and stores nothing. The control channel only has optional server-side TLS (`docs/grpc-tls.md`). There is no CA, no enrollment, and SSH-installed agents never start the gRPC worker because nothing writes `OPENVMS_SERVER_ADDR`. `docs/PRD.md` §71–72 requires a unique, revocable identity per agent and one-time-token enrollment.

## Decisions (user-approved design)

- **Identity**: agent cert carries tenant and `server_id` (`server_agents` is 1:1 with `frigate_servers`). Heartbeat derives the server from the peer cert and rejects a mismatching `node_id`.
- **CA**: internal CA generated by the API on first use; private key sealed in the DB with `OPENVMS_MASTER_KEY` (`internal/secrets`).
- **Enrollment**: one-time token (bound to `server_id`, 15 min TTL, stored hashed). The agent generates its own key and CSR; the API signs it. Private agent keys never touch the API. SSH install only drops the token and control-channel settings.
- **Lifetime / rotation**: 30-day certs; the agent renews over mTLS after two thirds of the lifetime.
- **Revocation**: issued-cert table checked on every connection.
- **Listener**: separate agent port (e.g. `:9443`) with `RequireAndVerifyClientCert`; the user/SDK port `:9090` is unchanged.
- **Heartbeat**: persists last seen, version and status.
- **Transport**: plain gRPC (no ConnectRPC migration).
- **Rollout**: opt-in by configuration; existing agents keep working until migrated.

## Scope

In: CA and issuance, enrollment token + CSR signing, agent mTLS listener with revocation, agent-side enrollment/renewal, persistent heartbeat, SSH install wiring, docs.
Out: API→agent HTTPS/bearer changes, bearer token rotation, ConnectRPC/bidirectional stream, compose port publication changes beyond what the listener needs, CA key rotation (follow-up).

## Acceptance criteria

- An agent without a valid client cert cannot call the agent listener; a revoked cert is rejected.
- A heartbeat with a `node_id` different from the cert identity is rejected.
- Enroll tokens are single use, expire, and are stored hashed; the API never sees agent private keys.
- Certs renew before expiry without operator action.
- Without the new settings, current behavior and tests are unchanged.
- `go build ./...`, `go vet ./...`, `go test ./...` pass; integration tests for new migrations pass.
