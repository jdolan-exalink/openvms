# Edge-agent version status, retry, and update lifecycle

Provide one honest lifecycle in the Servers screen: install when no agent is registered, update when a registered agent differs from the available edge-agent build, and disable the action only when the installed binary is verified current. Keep protocol version separate from binary release identity. Publish the requested edge-agent binary release as `0.1.1` by default in reproducible Compose and local build targets. After a safe pre-mutation SSH connection/authentication failure, let the operator retry by entering a fresh password; never retain or replay credentials.

## Accepted outcome and safety boundary

- **Scope**: OpenVMS edge-agent binary and its Servers UI action, not the web/browser client version.
- **Unified action**: no registered agent → **Install**; known registered build mismatch or legacy agent requiring upgrade → **Update**; exact verified build match → disabled **Up to date**. Unknown, offline, untrusted, or unsupported states must not be rendered as current or definitely outdated; show an explicit unknown/connection state and keep any action user-triggered.
- **Versions**: existing `0.1.0` protocol version stays unchanged as a distinct compatibility signal. Binary identity is derived from the exact artifact the existing install/update resolver supplies. Prefer exact SHA-256 equality as the update identity, with build version/commit labels only when embedded in or packaged with that exact trusted artifact bundle. Never use the API process version label as a substitute for the selected edge-agent artifact. The release display may use version/commit when available and must fall back to a short digest.
- **Health**: installed binary identity is reported only by the authenticated TLS health route and compared over the existing verified HTTPS transport using registered address and stored trust. There is no credentialed HTTP fallback. Older agents lacking TLS/build metadata are unknown/legacy, not falsely current.
- **SSH credentials**: a failed accepted job never keeps the root password. A retry is an explicit transition to an empty credential form requiring fresh input. Use generic connection/authentication wording; current SSH library errors do not reliably prove “wrong password.” Only a known pre-mutation connection-stage failure is retryable. Host-key mismatch and any staged/activation/health/rollback uncertainty are not retryable from the UI.
- **Identity and trust**: preserve server/agent IDs, tenant, Frigate configuration, sealed agent bearer, SSH TOFU record, and existing TLS trust. No trust reset, agent-token rotation, credential logging, automatic retry, or remote operation in verification.
- **TLS-enabled update**: update only the binary and compatible service/config files while preserving existing TLS certificate/key files and trust unchanged. Verify the pre-update registered TLS endpoint and the post-update health with the same stored public trust and bearer. If safe rollback cannot keep the old cert/key/trust usable, fail closed. Legacy TLS-disabled upgrade may use the existing bounded path that stages TLS material and records trust only after verified health.

## Route, TDD, and checks

- Route: delegated direct. This spans Go artifact resolution, agent TLS health, provision/API contracts, update runner, generated API clients, and Servers UI; reading/writing crosses multiple non-trivial files. Use one writer at a time and keep work units above separate.
- Strict TDD is enabled by `AGENTS.md`: observed RED before each implementation slice, then GREEN and REFACTOR. Go tests use table-driven behavior cases and fake artifact/SSH/HTTP seams only.
- Go verification: `make generate` when API schemas change; `GOCACHE=/tmp/openvms-go-build-cache go test -count=1 ./apps/edge-agent ./internal/agent ./internal/provision ./internal/api ./internal/store ./apps/api`; focused race `GOCACHE=/tmp/openvms-go-build-cache go test -race -count=1 ./apps/edge-agent ./internal/provision ./internal/api`; final `GOCACHE=/tmp/openvms-go-build-cache go test ./...`; `git diff --check`.
- Web verification: `(cd apps/web && pnpm exec vitest run src/routes/Servers.test.tsx)`, `(cd apps/web && pnpm typecheck)`, `(cd apps/web && pnpm test)`, plus scoped lint for changed paths.
- Runtime harness: fake artifact and SSH/TLS health dependencies; never start a listener, use real SSH, contact a camera, use an operator session, or deploy as part of unit verification.
- Forecast: likely exceeds 400 authored changed lines due cross-layer contracts, security tests, and generated types; heuristic only. Delivery strategy is `ask-on-risk`, chain strategy `stacked-to-main`; no PR/push/merge is authorized by this plan.
